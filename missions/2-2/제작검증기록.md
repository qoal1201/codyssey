# 게임을 만드는 기록

미션 2-1 기획서 초안. 기존 게임을 만드는 기록 블로그를 확인해 작성했다. 현재 홈에는 PHONE ARCADE/Handgun 개발 일지 5편이 보인다.

## 대상 사용자
- 게임을 만들며 생각과 진행 과정을 정리하려는 나.
- 게임 개발 과정과 배운 점을 읽고 싶은 사람.

## 사용 목적
- 아이디어부터 제작과 플레이 확인까지, 게임을 만들며 내린 결정과 배운 점을 날짜순으로 기록한다.
- 독자는 프로젝트와 날짜를 따라 개발 일지를 읽는다.

## 화면 구성과 동작
- 위쪽에 블로그 이름과 ‘모든 기록’, ‘소개’ 메뉴가 있다.
- 첫 화면에 블로그 소개와 개발 일지 목록이 나온다.
- 목록은 오래된 글부터 보여 주며, ‘전체’와 프로젝트 분류로 글을 거른다.
- 글 카드에는 날짜, 분류, 제목, 짧은 소개가 나오고 제목을 누르면 글을 읽는다.
- 글에는 제목, 날짜, 프로젝트·분류, 본문과 목차가 있다. 목차를 누르면 해당 부분으로 이동하고, 이전 글과 전체 목록으로 돌아갈 수 있다.
- 하단에는 블로그 소개와 홈으로 가는 링크가 있다.

## 필요한 자료
- 글마다 날짜, 프로젝트명, 분류, 제목, 짧은 소개, 본문과 소제목.
- 이전·다음 글 연결 정보.
- 그림을 사용할 때는 설명과 대체 텍스트. 실제 화면이 아닌 시안은 시안이라고 표시한다.
- 결정한 내용, 직접 확인한 결과, 아직 확인하지 못한 내용을 구분해 쓴다.

## 완료 기준
- 첫 화면에서 블로그 소개와 개발 일지 목록을 읽을 수 있다.
- 분류를 바꾸면 해당 글만 보이고, 표시된 글 수가 목록과 맞는다.
- 글 제목을 누르면 맞는 글이 열리고, 목차·이전 글·전체 목록 링크가 동작한다.
- 글에서 계획과 실제 확인 결과, 미검증 사항을 구분할 수 있다.

## 추가 기능
- 현재 별도로 추가할 기능은 정하지 않았다.

## 한계 및 비목표
1. 글을 사이트에서 직접 작성·수정하는 기능은 이번 범위에 넣지 않는다.
2. 로그인, 댓글, 좋아요 기능은 이번 범위에 넣지 않는다.
3. 기존 글에 없는 내용이나 확인하지 않은 결과를 새 사실처럼 추가하지 않는다.

## 검증 방법
- 홈의 글 제목·날짜·분류·소개를 각 글과 대조한다.
- 분류별 글 수와 실제 목록을 비교하고, 글·목차·이전 글·전체 목록 링크를 눌러 확인한다.
- 본문과 그림 설명에서 계획, 직접 확인, 미검증 상태가 뒤섞이지 않았는지 확인한다.

구현 요청:
- CSS와 필요한 JavaScript를 이 HTML 파일 하나에 모두 넣어. 외부 라이브러리, 외부 이미지, 외부 글꼴, API, 로그인, 서버를 사용하지 마.
- 단순하고 읽기 쉬운 한국어 게임 개발 일지 화면을 만들어. 헤더의 ‘모든 기록’과 ‘소개’는 해당 영역으로 이동해야 해.
- 다섯 글을 날짜 오름차순으로 표시하고, ‘전체’와 ‘Handgun’ 필터 버튼으로 목록을 바꿔. 두 버튼 옆 숫자는 각 목록 수와 맞아야 해.
- 글 카드마다 날짜, 분류, 제목, 소개를 표시해. 제목이나 ‘기록 읽기’를 누르면 해당 글의 정확한 원문 URL이 열린다. 원문에는 로그인이 필요하지 않다.
- 소개 영역과 홈으로 돌아가는 링크를 넣어. 빈 결과 안내와 키보드 포커스 표시도 포함해.
- 글 본문 전체는 이 HTML로 옮기지 않아도 된다. 실제 자료에 없는 글 내용을 만들지 말고, 원문 링크를 제공해.
- 화면 폭이 좁아져도 가로 스크롤 없이 읽고 버튼을 누를 수 있게 해.
- 기획서 밖 기능은 넣지 마.
- 브라우저에서 바로 열 수 있는 완성된 단일 HTML 코드만 출력해. 코드 펜스나 설명은 붙이지 마.

# 게임 개발 기록 페이지: 문제 수정과 사용자 테스트

## 기준 산출물

- 기준 기획서: [미션 2-1 기획서](../2-1/기획서.md)
- 기준 결과물: [미션 2-2 결과물](../2-2/게임개발기록_v1.html)
- 미션 2-2 기록에는 기본 목록·필터·원문 링크·375px 화면 확인 결과가 있습니다. 문제 수정과 사용자 테스트는 다음 미션으로 넘겼습니다.
- 미션 7 양식과 예시는 [`references/미션7_샘플/`](references/미션7_샘플/)에 보존합니다.

## 대상 사용자

- 게임 개발 기록을 읽고 싶은 사람.
- 테스트 참여자가 제작자 본인이면 기존 제품 지식을 함께 기록하고, 처음 쓰는 독자의 독립 테스트와 구분합니다.

## 사용 목적

- 독자가 기록을 찾고 원문으로 이동하는 과정을 확인합니다.
- 직접 확인한 문제와 실제 사용자 피드백만 근거로 결과물을 고칩니다.

## 화면 구성과 동작

- 기존 결과물의 홈 소개, ‘모든 기록’·‘소개’ 메뉴, 다섯 편의 목록과 원문 링크를 유지합니다.
- ‘전체’와 ‘Handgun’ 필터, 표시 수, 선택 상태와 결과 수가 서로 맞는지 확인합니다. 현재 다섯 편 모두 Handgun이므로 두 필터가 같은 다섯 편을 보여 줍니다. 사용자가 이 점을 이해하는지도 살펴보되, 새 분류나 글을 임의로 추가하지 않습니다.
- 키보드로 메뉴와 필터를 이동·선택할 수 있는지, 포커스 표시가 보이는지 확인합니다.
- 좁은 화면에서도 목록과 소개를 읽고 조작할 수 있는지 확인합니다.

## 필요한 자료

- 기존 다섯 글의 날짜, 제목, 소개, 프로젝트 분류와 원문 주소.
- 기존 HTML의 직접 확인 결과.
- 사용자 테스트에서 실제로 관찰한 행동, 질문과 피드백.

## 완료 기준

- 결과물은 미션 2-2의 `v1`을 덮어쓰지 않고 미션 2-3의 새 버전으로 보존합니다.
- 다섯 글의 표시 정보와 원문 주소가 기존 블로그 자료와 맞습니다.
- 메뉴, 목록 필터와 개별 원문 링크의 동작을 확인하고 결과를 기록합니다.
- 키보드 조작과 좁은 화면에서 확인한 실제 결과를 기록합니다.
- 참여자에게 설명을 먼저 하지 않고 정해진 과제를 부탁한 뒤 행동과 질문을 기록합니다. 제작자 본인이 참여한 경우에는 그 사실과 사전 지식을 함께 적습니다.
- 발견한 문제는 기획과 관찰에 근거해 필요한 범위만 수정하고, 수정한 동작과 관련 회귀 항목을 다시 확인합니다.
- 아직 실행하지 않은 테스트나 실제 참여자가 없는 사용자 테스트는 완료로 표시하지 않습니다.

## 추가 기능

- 이번 미션에서 새 기능은 정하지 않았습니다.

## 한계 및 비목표

1. 새 글, 새 프로젝트 분류, 글 작성·수정 기능을 추가하지 않습니다.
2. 원문 블로그의 내용이나 동작을 변경하지 않습니다.
3. 현재 필터 데이터로는 빈 결과 화면을 만들 수 없으므로, 가짜 자료를 넣어 빈 상태를 시험하지 않습니다.
4. 사용자 테스트에서 나오지 않은 피드백이나 결과를 만들어 쓰지 않습니다.

## 검증 방법

- 모든 글의 날짜·제목·소개·주소를 원문 자료와 대조하고, 각 링크를 직접 엽니다.
- 메뉴 이동, 필터별 표시 수·선택 상태·목록, 키보드 조작과 좁은 화면을 브라우저에서 직접 확인합니다.
- 별도 안내 없이 ‘가장 최근 기록을 찾아 원문을 열어 주세요’, ‘이 사이트가 어떤 기록을 모아 두는지 살펴보고 목록으로 돌아와 주세요’, ‘Handgun 기록만 보고 싶다면 어떻게 할지 보여 주세요’라고 부탁합니다. 탐색·필터·소개 이동에서 보이는 행동과 질문을 적습니다.
- 각 수정 후 실패한 확인과 관련된 기존 확인을 다시 실행하고 실제 결과를 제작·검증 기록에 남깁니다.

## 진행 결정

- 사용자 확인: 이 미션에서는 새 AI 결과를 비교하지 않고, 미션 2-2에서 선택한 `v1`을 이어 검증합니다.
- 기존 AI 비교와 선택 근거는 [미션 2-2 제작·검증 기록](../2-2/제작검증기록.md)을 참조합니다.
- 공식 안내문은 저장소에 보관되어 있지 않으므로, 추가 요구가 확인되면 범위를 반영합니다.
